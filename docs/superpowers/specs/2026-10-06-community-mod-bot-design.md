# Дизайн: Telegram-бот-модератор для крупных сообществ (SaaS)

Дата: 2026-10-06
Статус: утверждён

## Продукт

Бот-автоматизатор для владельцев Telegram-сообществ (от 5000 участников) — заменяет ручной
труд администрирования чата. Мульти-тенантный SaaS: один код обслуживает тысячи чатов.

### Целевая аудитория

- Владельцы крипто- и трейдинг-сообществ.
- Админы чатов поддержки и брендов.
- Менеджеры платных мастермайндов и закрытых клубов.
- Организаторы локальных сообществ.

### УТП

«Модератор, который настраивается за 3 клика» + точная статистика активности.

## Технический стек

- Язык: Python 3.12+, фреймворк `aiogram 3.x`.
- БД: PostgreSQL (обязательно), ORM `SQLAlchemy 2 async` (`psycopg3`).
- Миграции: `alembic`.
- Конфиг: `pydantic-settings` через env.
- Линт/типы/тесты: `ruff`, `mypy`, `pytest` + `pytest-asyncio`.
- Деплой: docker-compose (`bot` + `worker` + `postgres`). Dev — polling, prod — webhook
  (по флагу конфига).

## Архитектура

Модульный монолит: один бот-процесс обслуживает все чаты; тяжёлый фоновый код вынесен
во второй процесс `worker`.

### Компоненты monorepo `tg_botSaas`

```
bot/
  app.py             # точка входа (polling/webhook по флагу)
  config.py          # env-конфиг (pydantic-settings)
  db/                # SQLAlchemy async engine, сессии
  models.py          # ORM-модели
  modules/
    antispam/        # фильтры: ссылки, капс, повторы, стоп-слова
    greeting/        # приветствие + кнопки-ссылки
    captcha/         # верификация новичков («Я человек»)
    scheduler/       # автопостинг по cron
    stats/           # активность, топ, динамика роста/оттока
  billing/           # тарифы, лимиты, Telegram Stars
  support/           # общие хелперы: права, middleware, ошибки
migrations/          # alembic
worker/              # процесс: шедулер + агрегация статистики + таймауты капчи
tests/
docker-compose.yml
Makefile              # test / lint / typecheck / dev
```

### Мульти-тенантность

- Единый бот добавляется в каждый чат как администратор (нужны права на удаление сообщений
  и ограничение участников).
- Конфиг каждого чата — запись `Chat` (настройки как `jsonb`), тариф.

### Модели БД (ядро)

- `Chat` — chat_id, настройки `jsonb`, `plan`, `member_count`, `branding_flag`.
- `Moderator` — админы, подключившие/управляющие ботом (chat_id ↔ user_id).
- `Member` — участник в чате: user_id, warn_count, joined_at, left_at.
- `MessageLog` — лог срабатываний фильтров: user_id, тип фильтра, результат, время.
  Текст сообщения не храним (меньше персональных данных и объёма).
- `ChatMemberEvents` — события enter/leave для статистики.
- `DailyStats` — агрегаты по дням на чат.
- `CaptchaChallenge` — активные капча-задачи (chat, user, expires_at).
- `ScheduledTask` — задачи автопостинга: cron, текст, chat_id.
- `PaidPlan` — платежи/подписки: chat_id, plan, starts_at, expires_at.
- `ErrorLog` — залогированные исключения.

## Функциональные модули

### Анти-спам (`antispam`)

- Правила хранятся в настройках чата (`jsonb`); у каждого правила — поведение:
  `delete` / `delete+warn` (никак не «только warn» без удаления не нужно в MVP).
- Фильтры MVP:
  - ссылки (regex + whitelist разрешённых доменов);
  - КАПС: >70% букв в верхнем регистре и длиннее N символов;
  - повторы: одинаковое сообщение того же юзера за N минут;
  - стоп-слова: список админа.
- Срабатывание → запись в `MessageLog`, `warn_count+1`, бан после N варнов.
- На бесплатном тарифе действуют только предустановленные базовые фильтры; гибкие правила —
  на `pro`.

### Приветствие (`greeting`)

- Триггер: `chat_member` update (join).
- Текст и кнопки-ссылки — из настроек чата.
- Брендинг-строка «Работает на базе @bot»: флаг `show_branding`;
  на бесплатном тарифе принудительно включён.

### Капча (`captcha`)

- При join бот постит сообщение с кнопкой «Я человек».
- Нажатие кнопки не доставляется боту напрямую (нет callback); решение фиксируется по
  любому следующему действию (сообщение) в течение окна, либо по явному callback-ханду
  кнопки, если она прикреплена к сообщению бота как inline-кнопка и бот обрабатывает
  `callback_query`.
  → Решение: используем inline-кнопку «Я человек» на сообщении бота; время ожидания
  отслеживает `worker` по `CaptchaChallenge.expires_at`. По истечении — `restrict`
  (навсегда/на время — параметр чата).

### Шедулер (`scheduler`)

- `ScheduledTask`: cron-выражение + текст (+ опционально часы/таймзона).
- `worker` раз в минуту выбирает задачи, чей cron совпал, и отправляет сообщение в чат.
- Доступен на `pro`.

### Статистика (`stats`)

- Источники: `MessageLog` (счётчики), `ChatMemberEvents` (join/leave).
- `worker` раз в час аггрегирует в `DailyStats`: уникальные активные за день, новые,
  ушедшие, суммарная активность.
- Админу через `/stats`: активность за 7 дней, топ-10 участников, динамика роста/оттока.
- Продвинутая статистика — на `pro`; на free — только базовая сводка.

## Тарифы и оплата (`billing`)

### Тарифы

- `free`: до 1000 участников — базовый анти-спам, приветствие, капча, базовая сводка,
  брендинг принудительно. Цель — захват рынка.
- `pro`: свыше 1000 участников, далее платно: продвинутая статистика, гибкие правила,
  шедулер, удаление логов, без брендинга. Стартовая цена $10/мес, выставляется в Stars
  по курсу Telegram (значение цены в Stars — из конфига).
- `enterprise`: на будущее — `pro` без лимитов, кастомный брендинг, API. В MVP только
  фундамент (снятие лимитов).

### Логика

- Команда «Апгрейд» → `sendInvoice` (Telegram Stars).
- `pre_checkout_query` → подтверждение; `successful_payment` → `Chat.plan=pro`,
  запись `PaidPlan` c `expires_at`; продление — рекуррентные платежи Telegram Stars.
- Контроль лимитов: при `ChatMembersUpdated` пересчитываем `member_count`; превышение 1000
  на `free` → выключаем расширенный функционал и шлём админу напоминание.

## Обработка ошибок и безопасность

- Middleware-логгер: исключение в handler → запись в `ErrorLog` + alert суперадмину
  (fatal только).
- `TelegramAPIError` retry-able — retry с backoff, процесс не падает.
- Админ-действия идемпотентны (unique-констрейнты в БД).
- Каждый изменяющий хендлер проверяет права через `get_chat_member` (owner/administrator);
  сервисные команды — только `SUPERADMIN_IDS` из env.
- Секреты не пишутся в БД/логи.

## Окружение разработки и тестирование

- docker-compose: `postgres`; локально `python -m bot.app --polling`.
- `make test` — pytest (юнит: фильтры антиспама табличными кейсами, cron-матчинг,
  подсчёт статистики; интеграция: хендлеры на мок-сервере Telegram, БД).
- `make lint`, `make typecheck`.
